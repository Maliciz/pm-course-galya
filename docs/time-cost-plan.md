## 9. Рефлексія

| Питання | Відповідь команди |
|---------|------------------|
| Наскільки оцінка в годинах (Subtasks) збіглась зі Story Points? Який коефіцієнт вийшов? | Для 5 Stories у Sprint 2 (14 SP) декомпозиція на 14 Subtasks дала 45 год — коефіцієнт **3.21 год/SP**. Для простих 3-SP історій (`GB-17`, `GB-13`) вийшло стабільно по 9 год (3.00 год/SP), а для задач із макетами або Telegram API (`GB-16`, `GB-18`, `GB-19`) — 3.33–3.50 год/SP через час на налаштування інтеграцій і перевірку крайніх випадків. |
| Чи змінилось розуміння термінів після розрахунку через Velocity? Встигаєте до кінця семестру? | Так, ілюзія «встигнемо за 3 спринти» зникла. За реальної Velocity Sprint 1 (13 SP) обсяг MVP (63 SP) потребує 5 спринтів, і навіть без урахування паузи після Sprint 1 дата релізу виходить за межі 18.12.2026 (орієнтовно 11.01.2027). Щоб здати працездатне MVP до 18.12.2026, команді потрібно або підняти реальне навантаження з 8 до 12–15 год/тиждень на учасника (збільшити Velocity до 17–18 SP), або скоротити частину `Should Have` історій (`GB-16`, `GB-18`, `GB-19`). |
| Що показав CPI/SPI за Sprint 1 і що команда зробить інакше у Sprint 2? | `CPI = 2.50` показав формальну економію бюджету через те, що команда реально працювала 80 год замість закладених 200 год, але `SPI = 0.72` зафіксував зрив обсягу: `GB-12` (5 SP) не встигли закрити вчасно. Також у Sprint 1 ніхто не вів `Time Spent` у Jira, тож `AC` довелось оцінювати ретроспективно. У Sprint 2 всі учасники фіксуватимуть витрачений час безпосередньо в Subtasks щодня і розіб'ють задачі по ролях (`[BE]`, `[FE]`, `[QA]`, `[Design]`) із щоденною перевіркою прогресу. |
| Яка залежність виявилась найнебезпечнішою для проекту? | Критичний ланцюжок `GB-2 → GB-17 → GB-14 → GB-8 → GB-9 → GB-10 → GB-15` (39 SP) у поєднанні із зовнішньою залежністю `GB-22` (токен Telegram Bot API та хостинг). Будь-яка затримка в моделі розкладу і перерв (`GB-17`, `GB-14`) зупиняє весь модуль онлайн-бронювання (`GB-8`–`GB-10`, 21 SP), а блокування `GB-22` одразу затримує всі три задачі Telegram-сповіщень (`GB-15`, `GB-18`, `GB-19`). |
